## 0. 一句话结论

> AnythingLLM 是**开箱即用的本地 AI 工作台**，Personal Brain V1 是**可信记忆底座**。
> 前者赢在**触达与手感**，后者赢在**真相与边界**。
> 你想要的"智能"（OpenClaw / Hermes 式）**两者都不原生具备**——但**只有你的项目具备安全接上智能的地基**。

## 3. 按你的四条判据分别给结论

### 3.1 效率

**AnythingLLM 的效率**来自"零配置 + 现成生态"：下载、选模型、用起来；5400+ 技能和 MCP 让你不必自己造轮子。`[已验证]`

**你的项目的效率**来自另一处，而且更值钱：**上下文重建成本趋近于零**。
- 新客户端、无聊天历史、换账号——仍能恢复"已完成 / 剩余 / 相关模块 / 决策 / 约束 / 警告"（FR-053）。
- 验收口径是 **2 分钟内给出正确下一步**（SC-004，`spec.md:479`）。
- 精确问题（花了多少钱、还有什么待办）走**确定性聚合**，不靠语义猜（FR-020 / SC-003）。

**但你的效率现在兑现不了，瓶颈不在能力，在入口。**
- 事实：全仓没有任何外部消息通道代码（grep 零命中），通知只能落到 owner Inbox（`us11-proactivity.md:18-20`）。
- 白话：你造了一台很好的发动机，但还没装方向盘——你必须先打开 TRAE/Cursor 才能用上它。
- **这是效率维度的第一优先级缺口，且它不是"缺功能"，是"链路断裂"**（能力在、触达断）。

### 3.2 质量

**你的项目在质量维度上是三者中最强的，且优势很大。** 证据不是文档，是代码里的硬约束：
- 授权：deny 优先、scope 交集、sensitivity ceiling、撤销立即生效（`security/policy.py:53-110`）`[已验证]`
- 幂等：唯一键 + payload digest + tombstone 不复活（`persistence/idempotency.py:83-201`）`[已验证]`
- 时间/金额：`numeric(20,4)`、"下午"保留为 12:00–18:00 窗口而非伪造 15:00（`records/time_policy.py:37-53`）`[已验证]`
- 模型调用：预算 / 超时 / 敏感度 / secret 拒绝，**fail-closed**（`models/gateway.py:70-109`）`[已验证]`
- 验收：197 项任务已勾 195、322 个测试用例、25+ 份带 RUN_ID 的验收证据 `[已验证]`

AnythingLLM 的质量是**产品级质量**（好用、迭代快），不是**契约级质量**（可证明、可审计）。两者不是同一把尺子——它不需要证明"为什么相信这条记忆"，你需要。

**但有一处真实的质量缺口（不是文档问题，是代码没跟上规范）**：
- 规范：ER-03 要求排序决胜项为「显式来源等级 → 有效时间 → importance → object_id」，并要求把 confidence/freshness 的影响写入 `ranking_reasons`（`execution-rules.md:40`）。
- 现状：`rank_hits` 只用了 RRF 分数 + freshness 布尔 + object_id（`retrieval/ranking.py:34-42`）`[已验证]`；全仓 grep `ranking_reasons` **只在规范里出现，代码里零实现** `[已验证]`；`importance` 只作为领域字段存在，从未参与排序 `[已验证]`。
- 影响：FR-057 声称的"排序考虑 confidence / 来源信任 / importance"目前**名不副实**。这是一条"规范已写、实现未做"的悬空条款。

### 3.3 智能（你最看重的一维）

先做一次概念切分，否则这一维没法谈：

| 词 | 含义 | 谁能提供 |
|---|---|---|
| 聪明 | 模型本身的能力（推理、写作、知识） | 换模型即可，**不是系统能力** |
| **智能** | **决策 → 执行 → 观察 → 再决策 的闭环**（能自己把事做完） | 需要 harness |
| 智慧 | 知道什么该做、什么不该做，并长期一致 | 需要记忆 + 价值约束 |

按这个切分，结论很清晰：

- **你的项目有"智慧"的地基，没有"智能"的闭环。** 它知道"什么该做/不该做"（A/B/C 分级、确认门、风险分类），但它**不会自己去做**。
- AnythingLLM **有闭环但智慧薄**：Scheduled Jobs 能定时跑 Agent、能调工具、能推送 `[已验证]`，但它的"记忆"是 chunk，没有证据纪律，也没有"这条记忆凭什么成立"的答案。
- OpenClaw / Hermes 是**闭环 + 通道**的成熟形态：Gateway → Runtime(SOUL/Memory/Skills) → LLM → Tools 的循环，一条消息可以触发几十次工具调用；记忆落地为本地 Markdown（`MEMORY.md` + 每日笔记 + 语义召回）；有 cron / heartbeat / webhook 主动触发；25+ 通道触达 `[已验证]`。

**关键判断（这是整份报告最重要的一句）：**

> 你的项目缺的不是"循环代码"，而是**循环可以安全落地的两个前提**——而这两个前提，**只有你已经建好了**。
> - 前提一：**权威状态**。循环会产生副作用，副作用必须有唯一权威归属，否则重放、并发、离线都会撕碎状态。你有（FR-001/ER-07）。
> - 前提二：**权限与确认门**。循环会自主行动，自主行动必须有边界和确认。你有（ER-06，高风险强制 CONFIRMATION_REQUIRED）。
>
> AnythingLLM 和 OpenClaw 的循环是"裸奔的"——它们跑得快，但没人能回答"这一步为什么被允许"。你的循环一旦接上，是三者中唯一**可审计、可回滚、可证明**的。

反过来说，你的项目**当前契约层从根上不表达"动作"**：
- `FR099_TOOL_NAMES` 30 个工具（`protocols/tools.py:32-40`）`[已验证]`，动词只有 `save / add / complete / start / checkpoint / finalize / record / create / propose / upload / sync / get / list / search / answer / check`。
- **没有一个动词是"执行 / 发送 / 调用 / 打开 / 运行"。**
- 白话：这 30 个工具是"笔记本"，不是"手"。你在笔记本上写"我要去取快递"，笔记本不会去取。
- 举例：`answer_brain` 的模型调用被硬限为 `ProviderCallBudget(max_calls=1)`（`api/authorized_tools.py:266-274`）`[已验证]`——**一次调用，没有第二轮**。这就是"闭环"不存在的最直接证据。

### 3.4 功能全面

- **广度**：AnythingLLM ≈ OpenClaw > 你的项目。它们覆盖文档、会议、浏览器、定时任务、多通道、图像、语音；你覆盖的是"记录 + 记忆 + 项目 + 权限 + 恢复"这条纵深。
- **纵深**：你的项目 > 两者。你有的东西（证据血缘、删除账本、隔离恢复验证、freshness 契约、幂等墓碑）它们一个都没有。
- **判断**：你不需要在广度上追平它们——追平是填不满的坑，而且会稀释你最值钱的东西。**你需要的是给纵深加一个出口。**

## 5. 结论与建议路径

### 5.1 结论

1. **不要在广度上和 AnythingLLM 竞争。** 它是产品，你是底座；它的功能列表不是你的路线图。
2. **你的稀缺性在"可信"，不在"聪明"。** 三者中只有你能回答"我为什么相信这条记忆"和"这一步是谁允许的"。
3. **"智能"对你而言 = 给你的可信状态装一双手和一个闹钟。** 手 = 动作型工具 + 受控循环；闹钟 = 调度器 + 通道。
4. **最大风险不是"做不出来"，而是"做错了顺序"**：先加通道（外部代发面）后加确认门，会一次性毁掉 ER-06 的全部积累。

### 5.2 建议路径（分四步，每步都可独立验收）

| 步 | 做什么 | 为什么先做它 | 验收口径 |
|---|---|---|---|
| S1 | 补 ER-03 排序账（G6/G7） | 零风险、纯还债；且是后面一切"排序可信"的前提 | `ranking_reasons` 出现在检索返回里；importance/来源等级参与决胜 |
| S2 | 建"动作型工具 + 受控循环宿主"，**只在 Brain 侧**，先做只读动作（读取、检索、计算） | 先把闭环跑通，但不引入外部副作用 | 一次请求可产生 ≥2 轮工具调用，且每轮都过权限/预算门 |
| S3 | 加"有副作用的动作"（写文件、发通知、调外部 API），**每个动作强制走确认门 + 落 canonical 事件** | 副作用是事实，必须进证据链 | 每个动作有 operation_id、可回滚、可在审计里重建 |
| S4 | 加通道（先 Inbox 增强，再 1 个外部通道） | 触达是效率兑现点，但也是最大安全面 | 通道失败不影响 core health；外部代发必须显式授权 |
