## 决策落地（已拍板）

| 决策 | 采纳 | 落地方式 |
|---|---|---|
| D1 后台 LLM 预算 | (b) | 后台 LLM 作业按"每日配额"管控：`BRAIN_LLM_DAILY_QUOTA`（默认 200 次/日，按所有者、按本地日统计已启动的 LLM 类作业数）；单次仍走 ModelGateway 有界调用（max_calls=1、60s 超时、敏感度约束、fail-closed）。超额时作业完成但记录 `skipped=daily_quota_exceeded`，不阻断写入。 |
| D2 抽取落地 | (b) | 抽取出的候选自动写入 `self_claims`（policy_class=B、lifecycle=candidate、establishment=candidate），并写 `evidence` 行；A/C 类不自动生成。 |
| D3 Digest 频率 | (a) | `daily_digest` 每日 03:10（本地时区）生成前一天、按 scope 分组的摘要。 |
| D4 冲突强度 | (a) | 冲突仅写 `conflicts` + `review_inbox_items`（Inbox），不自动降 confidence。 |

## Δ1 调度器（"活"的地基）

- 新增 `apps/worker/personal_brain_worker/scheduler.py`：
  - `DailySchedule(job_type, hour, minute)`；内置 `DEFAULT_SCHEDULES`：
    `daily_digest 03:10`、`promote_candidates 04:10`、`retention_sweep 04:20`、
    `conflict_scan 04:30`、`retention_maintenance 04:40`、`health_check 08:00`（本地时区）。
  - `PeriodicScheduler.tick()`：遍历所有 owner × schedule，按本地日到期后入队一次；
    幂等键 `uuid5(NAMESPACE_URL, "brain-schedule:{owner}:{job_type}:{bucket}")`，
    入队前查重（Postgres 下加事务级 advisory lock 防并发双写）。
  - 作业 `payload_ref = "schedule:{job_type}:{bucket}"`，`client_id=NULL`（系统作业）。
  - 与 WorkerLoop 组合：`__main__.py` 的 poll 里调用 `scheduler.tick()`（内部 60s 节流）。
- 验收：jobs 表出现周期性作业类型 ≥2 种；同一天重复 tick 不重复入队；跨天入新作业。

## Δ2 抽取派生接通（LLM 用起来·第一批）

- **契约变更（有意）**：`save_note` 的入队从 1 个作业变为 2 个：
  `index_raw_input`（纯检索投影）+ `extract_raw_input`（LLM 结构化抽取）。
  注册表同步拆分：`index_raw_input → index`，`extract_raw_input → extract`。
  受影响既有测试按新契约更新（保持原测试意图不变）：
  `tests/migration/test_full_chain_postgresql.py`（改成排 `index_raw_input`）、
  `tests/integration/test_authoritative_store.py`（save_note 后 jobs 数 7→8）。
- 新增 `apps/worker/personal_brain_worker/extraction.py`（`EXTRACTION_VERSION="extract-v1"`）：
  1. 读 raw_input（active、有文本）；已被同一版本抽取过 → 幂等重放；
  2. 无 gateway → 完成并记录 `skipped=provider_unavailable`；超日配额 → `skipped=daily_quota_exceeded`；
  3. 经 ModelGateway 有界调用（提示词要求输出严格 JSON：`summary` + `candidates[]`，类别限 9 个枚举）；
  4. 解析失败 → `BRAIN_UNAVAILABLE`（可重试，最多 5 次后死信，诚实失败）；
  5. 单事务落库：`derived_contents(kind='description')` + 存储层存 JSON 载荷 +
     `derivation_edges(extracted_from)`；每条候选 → `self_claims`(B/candidate) +
     `evidence` 行 + `derivation_edges(inferred_from)` + `index_self_claim` 作业。
- 防退化：金额/待办不经过 LLM；派生只写 derived + candidate；`context` 记录 `来源渠道:作用域`。

## Δ3 画像自演化接线（第二批）

- 新增 `apps/worker/personal_brain_worker/evolution.py`：
  - `promote_candidates`：A 类候选激活为 active；B 类按（去否定词主题签名 + 极性）分组，
    调 `assess_b_promotion`（≥3 来源 / ≥14 天 / ≥2 上下文 / ≥1 直接陈述 / 无矛盾）→
    满足则最早一条晋升 established，`correction_events` 留痕并刷新索引作业；
    组内存在相反极性 → 整组暂缓（矛盾阻断）。
  - `retention_sweep`：调 `lifecycle.retention_transition`（A 类豁免；B 候选 >90 天过期、
    established >180 天转 historical）；过期条目删除其检索索引；`correction_events` 留痕。
  - `conflict_scan`：established × candidate 同主题签名、极性相反 → 写 `conflicts`（open）+ 
    `review_inbox_items`(item_type=conflict) + `notify_review` 作业；按 subject_refs 去重。
  - `retention_maintenance`：接入既有 `prune_rebuildable`（旧成功作业清理）。
- 验收：同类偏好 3 次（跨 14 天、2 上下文）自动升级；90 天候选归档；构造矛盾进 Inbox。

## Δ4 主动智能（Digest + 克制的主动）

- 新增 `apps/worker/personal_brain_worker/digest.py`：
  `daily_digest` 处理前一天窗口，按 `intake.requested_scope` 分组；
  每组经 ModelGateway 生成摘要（配额同 Δ2），落 `derived_contents(kind='digest',
  target_type='scope', target_id=uuid5(...))` + 存储载荷 + 检索索引（含向量，若可用）
  + `derivation_edges(summarized_from)` 逐条回指 raw_input；`source_links` 100% 可回溯。
- `job_handlers.health_check` 扩展：存在 dead_letter 作业 → 写 `notifications`
  （trigger=brain_health_failure，inbox，queued）+ 排 `dispatch_notification`（去重/冷却复用
  `notification_policy.decide_send`）。
- 验收：digest 行可查、可被检索命中；失败作业产生通知记录。
