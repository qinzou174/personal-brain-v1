## 〇、我理解的真实系统（白话，讲给外行听）

Personal Brain V1 是跑在你自己机器上的"唯一长期记忆库"。它有**两个实例**：Windows 本机（127.0.0.1:18082，合成数据，模型已激活）和局域网服务器（192.168.10.7:18081，真实数据域，生产形态）。使用方式：你通过 TRAE CN / 手机 / 任意 MCP 客户端调用它的 30 个工具——记笔记（save_note）、记账（add_expense）、待办（add_todo/list_todos/complete_todo）、搜记忆（search_brain，全文+向量）、问问题（answer_brain，真实模型接地回答）、项目连续性（create_project/start_task/checkpoint/finalize + module freshness）、自画像（propose_self_claim/get_self_context，A/B/C 分级）。

它怎么保证可信：任何输入先存原文（raw-first），派生结果（摘要/标签/画像）可追溯回原文；客户端访问先查权限（权限先于检索）；不确定/冲突/删除进 Inbox 或要确认；离线诚实报"未保存"。长期可靠性靠：Alembic 迁移链 0001..0012、备份脚本（backup/verify-restore/migrate）、加密备份集 + 隔离恢复验证（已实测 6/6）。

## 一、我理解的内核（不抄条文）

**一句话**：造的是"任何 AI/客户端可换、你的记忆与项目历史不消失"的服务端唯一权威个人记忆库。

**不可让渡公理（工程上最易踩塌形态）**：
1. 原始先于派生 —— 原文永存、派生可重建；（易塌：摘要覆盖原文）
2. 权限先于检索 —— 查不到权限外内容、拒绝留审计；（易塌：先搜后滤）
3. 诚实优先于成功 —— 离线报"未保存"，不假成功；（易塌：pending 标 saved）
4. 高风险必确认 —— C 类画像/删除/权限无确认不执行。（易塌：delete 直删）

**辨析例**：本机 `get_operation_status` 对随机 id 返回 `-32601 NOT_FOUND` —— 这是"诚实报告不存在"，不是 bug；同理模型未激活时 `answer_brain` 返回 TOOL_DENIED 而非瞎编。这套"诚实优先"正是它能当长期记忆库的根基。

## 三、分层根因（为什么"生产"还差几颗螺丝）

1. **日志轮转缺失根因**：T042 compose 初版只写了 healthcheck，未写 `logging` 段；FR-093 的要求被"docker 默认 json-file 无限增长"掩盖——**没被触发过**所以没暴露（本机日志量小）。独立修法：compose 加 `logging: driver: json-file, options: max-size/max-file`。
2. **异机备份未闭环根因**：备份脚本验证做了，但"把备份集送出本机"需要第二个目的地（NAS/云盘/另一台机）——属于**环境决策未拍板**，非代码缺陷。
3. **健康详情未暴露根因**：`health.py` 实现了 doctor 检查（FR-092 全套），但对外端点只保留精简 `alive`，诊断详情没走 MCP/API 暴露给客户端。独立修法：扩展 `/health` 或加 `doctor` 工具返回完整字段。
4. **T186 未闭环根因**：需要 HTTPS + 真实客户端账号。这是架构级外部门禁，mock 不替代（诚实原则）。

## 四、外部参照系（该学/不该学）

- **Obsidian + 插件生态**：该学"本地优先、文件即数据"；不该学无权限粒度（本项目必须 client×scope）。
- **Notion API 式个人数据库**：该学"结构化优先于自由文本"；不该学供应商锁定（本项目自托管）。
- **mem0 / 记忆层中间件**：该学"记忆分级+证据回溯"；不该学"自动无监督改写记忆"（本项目 A/B/C 确认门）。
- **自托管 wiki（Trilium/Logseq）**：该学"人工编辑与 AI 记忆分离"；不该学"让笔记界面成为权威源"（本项目 Brain 才是 canonical）。

**本项目独有约束**：单 owner、双端权威、行为验收 12 US + GWT、派生全部可重建、离线诚实、风险确认门 ER-06。

## 五、思维链（因为 X → 所以 Y → 预期 Z）

1. 因为 双实例 `/ready` 全绿 + 30 工具冒烟 36/36 + 核心 6 工具实测 5 OK → 所以 日常记录属性可用 → 预期：日常写/读不中断。

3. 因为 ranking_reasons 已接线（ER-03）→ 所以 检索可解释 → 预期：用户能追问"为什么这几条"。
4. 因为 备份+隔离恢复 6/6 实测 → 所以 数据可恢复 → 预期：灾难后能还原。
5. 因为 compose 无 logging 轮转 → 所以 长期运行磁盘可能被日志占满（FR-093 缺口）→ 预期：若不修，数月后磁盘告警。

## 七、设计 Delta（修正建议）

- **Δ1（低风险，推荐做）**：compose.yaml 为 api/worker/model-proxy 加 `logging` 轮转（json-file，max-size 50m，max-file 5）。依据 FR-093/§134。预期：磁盘有界。
