# 检查点清单（拉绳过程随时抽查，不是组织方式）

> 用法：每挖到一个环节，顺带对照以下检查点，命中即记。按 文件:行号 + 白话 + 严重度。
> 哲学依据：宪法 R1-R12、P12 对接哲学。

## A. 链路完整性
- A1 表被写没被读（死表）——SQLite schema vs 全 src 读点
- A2 字段被写未消费（死字段）——列名反向 grep
- A3 函数/方法无调用方（死代码）——vulture + grep
- A4 LLM trigger 产出无消费——trigger 名反向追消费者
- A5 状态写进 prompt 但表达层无人看
- A6 分支无消费：每分支都有消费者吗

## B. 哲学合规（本项目独有）
- B1 词表替判：情绪/念头/欲望关键词表当判定器（违 R7）
- B2 表达覆盖事实：聊天话术直通行为（违 R12）
- B3 替 AI 决定：强制回应/用户优先/系统造感受（违 R1/R3/R8）
- B4 装饰性复杂度：有写无读、只进日志不进行为（违 R10）
- B5 推断冒充事实：LLM 推断未标来源写长期记忆（违 R7/R8）
- B6 硬编码身份/人格（违 R5/引用式）
- B7 活动硬解码：情绪由标签不由经历（违 P12-4）
- B8 反哺事实守卫：表达前查"真发生过没"（违 R12）

## C. 工具与 LLM
- C1 死工具/死 schema/未接线开关
- C2 工具跨轮重复注入 / token 大户描述
- C3 LLM 调用产出→消费闭合（含多 tool_call 结果回传）
- C4 超时/重试/空响应边界（双层超时竞态、重试丢结果）

## D. 持久化与恢复
- D1 快照漏恢复（重启丢状态）
- D2 实例隔离：data_root 绑定一致性（衣柜/时间线等游离项）
- D3 配置/文档漂移（env 键、旧套餐键、注释与实际不符）

## E. 并发生命周期
- E1 双层超时竞态 / 外层抢先取消内层
- E2 后台任务孤儿/清理
- E3 跨循环锁正确性

## F. 交付
- F1 每条发现：白话 + 举例 + 证据文件:行号 + 严重度 + 断点
- F2 覆盖台账更新（哪些绳子走完/未走完）
