# Deep-Reflection（哲学落地的深度反思 · 思维链文档）

本 skill 的组织方式是**从理解到推导**，不是"检查清单式复核"：先把项目哲学真正读进脑子并用自己的话讲出来 → 找到"哲学要求 vs 现状"的差距及其**性质**（哲学错位 / 链路断裂 / 工程故障）→ 挖出**分层根因**（每层独立修法）→ 对照外部参照系（该学/不该学）→ 用显式思维链（因为X→所以Y→预期Z）推导设计 → 给出**后期可观察的表现指标** → 结论以 delta 形式落进设计稿。

**核心信念：方案是路径的结论，不是路径的前提。** 任何反思，先走通路径，方案从路径中自然长出来。

---

## 0. 认识论（灵魂层，先于一切流程）：反思是什么

**反思是一次认识行为，不是文档生产行为。**

- **反思的第一产出，是"我真正理解了这个模块/系统实际怎么运行、为什么这样运行"**；文档（差距矩阵/思维链/delta）是理解的留痕与副产品。判断反思是否到位，不看文档多完整，看**能不能把系统讲清楚**。
- **反思的用途**：让计划 / 方案 / bug 报告**精确、全面、合理**。精确来自对真实运行逻辑的理解，不来自流程步骤走完。**未经真实接触的判断 = 幻觉温床**——反思是主动去接触真实运行逻辑的机会，是对抗幻觉的武器。
- **bug / 异常是接触系统的入口（敲门砖心智）**：出现 bug 时，反思的动作 = 走进这个模块，理解它的实际逻辑，再搭配哲学与理念产出判断。bug 不只是"要修的东西"，更是"认识一个此前不理解的模块"的机会。
- **贴近真实、现实、实际**：一切结论向真实收敛——真实代码、真实日志、真实数据、真实运行路径；不向"看起来合理"收敛。
- **认识论底线（反幻觉硬线）**：反思产出中的每个关键判断，必须能回答"**我是怎么知道的**"——答案只能是"我实际看过（文件:行号/日志行号）"；答不出来 = 推断或幻觉，必须显式降级标注或移入待查。**禁止在未接触真实证据处下判断。**

## 0.5 铁律（违反任一条 = 反思无效）

1. **接触真实，禁止凭印象**（认识论的执行条款）。
   - 哲学文档必须**全文读**（至少 00-项目宪法、01-设计哲学、02-因果与连续性、10-核心术语与事实分层；领域相关加读 06/11/13/14）。
   - 被反思对象涉及代码时，**必须读真实代码**（文件:行号级），不得靠记忆或二手文档。
   - **读完的真实标准**：能用自己的话讲清"这个模块/系统**实际怎么跑、为什么这样跑**"（生产→处理→消费一句话）——讲不出 = 没读懂 = 不许进入下一步（禁止用流程进度掩盖理解缺失）。
   - **证据分层（反幻觉硬线）**：每个关键判断标注证据等级——`已验证`（实际打开并核对了 文件:行号 / 日志行号）｜ `推断`（逻辑推演，未核验）｜ `未知`（待查）。**禁止把"推断"写成"已确认"；禁止在"未知"处下判断**（只能列为待查项或决策点）。
   - 反例（真实事故）：v0.1 草案凭印象写"项目没有主体评审"，实际 `desire_board_reviewer.py` 早已存在完整实现 → 整份草案的诊断错位（违 R8 造第二套机制的风险）。
2. **先证明理解，再谈设计**。产出必须以"用自己的话复述哲学内核"开篇——精确到"这个项目在造什么"（不是"AI 陪伴系统"这类泛词），并从 R1–R12 提炼出工程上最易踩塌的**不可让渡公理**。引用编号 ≠ 理解；能用**一个具体的辨析例**讲清哲学边界才算过（示例：001 说"渴得冒烟"不是 bug——表达层忠实报告真实状态符合 R12，真 bug 是生活层断链；这个辨析直接改变了修法方向）。
3. **横向统计不算审查，纵向链路才算**。定位问题必须走"生产者 → 契约/变换 → 传输 → 持久化/索引 → 消费 → 最终行为"全链；只做告警签名/计数汇总 = 无效反思（反例：第一轮日志审查漏掉"001 六小时零结算"的头号问题）。
4. **诊断必须分性质**：**哲学错位**（功能都在、"谁在驾驶"错了——最高优先级）、**链路断裂**（该连的没连）、**工程故障**（接线坏了）。禁止把所有问题都说成"缺功能"。
5. **根因必须分层**，单一根因通常意味着没挖到底。每层给：白话 + 证据（文件:行号/日志行号）+ **独立修法**（分层修法可独立验收）。
6. **外部参照系必须带边界**：每引用一个开源/学术参照，必须写清「该学什么 / 不该学什么 / 本项目独有约束（为何不能硬套）」。本项目独有约束永远包括：多实例物理隔离、双端权威（A 私人 vs B 公共）、行为验收 B1–B12+GBC、人格引用式与第一人称红线。
7. **思维链显式化**：每条推演写成「因为 X（哲学/证据）→ 所以 Y（设计）→ 预期 Z（可观察结果）」。禁止"直接给方案 + 事后补理由"。
8. **哲学词汇权属哲学层**：方案中的状态名/阶段名/术语，必须逐字对齐 `10-核心术语与事实分层.md` 的词典（如行动状态：欲望→候选计划→已选择→进行中→部分完成/完成/失败/取消，取消保留原因）；**不得自造词**（反例：v0.2 自造"萌芽/合流/兑现"被修正为哲学词典）。
9. **后期表现必须可观察**：给出三线指标（最低线=不再有人受罪 / 中间线=像同一个人 / 高线=有社会性），每条带机检口径（现状值 → 目标值）与**反退化红线**（列出"不管哪期违反即失败"的项）。
10. **白话+举例（强制，项目规则）**：每个结论/发现/设计项必须配「白话」+「举例」；白话是解释层，不替代证据层。
11. **结论以 delta 落地**：若被反思对象已有设计稿，产出"相对上一版的 delta 清单（Δ1…Δn，含硬修正标记）"，而不是从零重写；并在文档头部登记到变更记录。

## 1. 触发与对象识别

用户说「反思 / 思考 / 审视 / 回顾 / 重新想 / 谈谈思考」某产出（设计草案、审查报告、方案、决策、某个功能），或一个设计/决策需要在推进前对照哲学自证时使用。

先明确三件事：
- **对象**：反思的是什么（文档路径 / 决策 / 功能范围）；
- **对象类型决定入口约束**（两类）：
  - **设计/方案类**：以被反思文档为主入口，但其声称触达的代码接缝必须逐一打开核验（讲清运行原理）。
  - **bug/异常类**：以**真实运行路径**为主入口——代码链路 + 日志/运行证据原行（bug 报告只是线索、不是证据）；先产出"模块实际怎么跑、坏在哪一环"的理解，再谈修复方案。
- **输入证据**：对象引用的全部材料（审查报告、代码、日志、哲学文档）；
- **输出位置**：本项目的反思产出放 `docs/tasks/design-<YYYYMMDD>-<主题>/`（如已有目录则续号），文件名惯例 `0N-思考路径.md` 或 `0N-草案反思与修正.md`。

## 2. 流程（九步，可裁剪但不可跳序）

```
0 理解真实系统（接触真实证据，能讲清运行原理）→ 1 自述内核 → 2 差距矩阵
→ 3 分层根因 → 4 参照系 → 5 思维链 → 6 表现指标 → 7 设计 delta → 8 交付与自检
```

1. **理解真实系统**（铁律 1；本步的产出是"理解"，不是"材料清单"）
   - 哲学：至少 `00-项目宪法.md`、`01-设计哲学.md`、`02-因果与连续性.md`、`10-核心术语与事实分层.md` 全文；记忆/关系/人格类主题加读 `11`；行为验收类加读 `06`；聊天域加读 `13`；多实例/世界对接加读 `14`。读完写下"这个系统为什么这样设计"各一句。
   - 对象与代码：被反思文档全文 + 其声称触达的代码接缝（函数/类/配置，落 文件:行号）。**对每个接缝产出一句"运行原理解释"**（输入从哪来 → 这一步做什么 → 输出去哪）；讲不出就继续读，直到能讲清。
   - **对象是 bug / 异常时（bug 入口约束）**：bug 是接触该模块的入口——必须走到真实运行路径（代码链路 + 日志/运行证据原行抽样），产出"这个模块实际怎么跑、bug 在哪一环破坏了什么"的理解；**禁止只读 bug 报告的转述就下判断**。
   - 日志/运行证据（如有）：引用既有审查台账 + 原始行抽样核验（不重做全量统计）。
   - **本步结束条件**：能用一段白话把"它实际怎么跑、为什么这样跑"讲给不读代码的人听懂。达不到 = 返回继续读。

2. **自述内核**（铁律 2）
   - 写"一句话：这个项目在造什么"；写 3–4 条**不可让渡公理**（我的提炼，非抄条文）；写**至少一个辨析例**证明理解（用真实运行案例说明某行为的哲学是非）。
   - 输出标题示例：「一、我理解的项目哲学内核（用自己的话，不抄条文）」。

3. **差距矩阵**（铁律 4）
   - 表：`哲学要求（出处） | 现状事实（证据：文件:行号/日志行号） | 差距性质（哲学错位/链路断裂/工程故障）`。
   - 逐行只表达一个可独立判定的命题；排序把"哲学错位"放前。

4. **分层根因**（铁律 5）
   - 挖 3–6 层错位（本次实例：频率错位 / 信息错位 / 权威错位 / 边界错位 / 因果耦合）；每层：白话一句 + 证据 + 独立修法。
   - **必须回答"为什么现有的机制会被架空"**——根因分析比"重建一个新机制"更有价值（优先修接缝，而不是造第二套）。

5. **参照系**（铁律 6）
   - 检索/引用 2–5 个开源或学术参照（如 BDI/Bratman 意图理论、Generative Agents 记忆流、CoALA 认知架构、双过程情感架构）。
   - 每个参照三段式：**它是什么（一句话）→ 对得上本项目什么 → 该学 / 不该学（边界）**。
   - 结尾必须写「本项目独有约束（所有参考都没有、不能硬套）」清单。

6. **思维链**（铁律 7）
   - 8–12 条「因为 X → 所以 Y → 预期 Z」；X 必须是哲学条款或带行号的证据，Z 必须可观察。
   - 思维链之后，**设计条目全部从链条中引用**（设计不得出现链条之外的东西）。

7. **表现指标**（铁律 9）
   - 三线表（最低/中间/高线）：指标名｜机检口径｜现状值｜目标值。
   - 反退化红线：4 条左右（示例：不许把裁量变词表 R7 / 不许表达层消费未完成状态 R12 / 不许脚本化 R3 / 不许用户话语直接成行为）。

8. **设计 delta**（铁律 11）
   - `Δ1…Δn`：每条含「改什么 + 依据（哲学/证据/参照）+ 预期 + （如涉及命名）哲学词典对齐检查」。
   - 同步更新原设计稿：状态头升级版本号、变更记录追加一行、相关小节内联标注 `ΔN`；新增决策点（D 编号续排）。
   - 决策点表格：`决策 | 选项 | 我的建议（含理由）`——把张力显式交给创始人拍板（如"主体裁量 vs 安全网"这类哲学张力不得自行消化）。

9. **交付与自检**
   - 交付物：①思维链文档（主交付）；②被反思对象更新（delta 并入）；③对话层白话总结（一句话结论 + 关键发现 + 待拍板项）。
   - 跑 `references/checklist.md` 自检，全过才算完成；未过项必须在交付中如实登记。

## 3. 反模式（见到就停手重做）

| # | 反模式 | 为什么致命 | 正确做法 |
|---|---|---|---|
| A1 | 凭印象写"项目没有 X" | 会造成结构性误判（真实事故：误判"无主体评审"） | 先 grep/读代码确认存在性 |
| A2 | 只做横向统计（计数/签名） | 漏掉纵向链路上的头号问题 | 走全链：生产→存储→消费→最终行为 |
| A3 | 引用 R 编号代替理解 | 无法发现"哲学错位"类问题 | 先自述内核 + 辨析例 |
| A4 | 把所有问题说成"缺功能" | 掩盖"谁在驾驶"的错位 | 差距性质三分类 |
| A5 | 单一根因 concluded | 修一处不动其余 | 分层根因 + 独立修法 |
| A6 | 硬套开源参考 | 忽略多实例/双端世界独有约束 | 参照必带"不该学"与独有约束 |
| A7 | 先方案后理由 | 方案不可验证 | 先思维链，方案从链条引用 |
| A8 | 自造状态名/术语 | 与哲学词典、验收、追溯对不上 | 逐字对齐 10 号文档词典 |
| A9 | 只给方案不给表现指标 | 无法验收、易回归 | 三线指标 + 反退化红线 |
| A10 | 替创始人消化哲学张力 | 越权决策 | 张力显式列为决策点 |
| A11 | **证据未分层（推断冒充已确认）** | 幻觉进入判断，方案/build 建立在错误前提上 | 每个关键判断标注 `已验证/推断/未知`；未知处不下判断 |
| A12 | **跳过系统理解直接产出（流程走完但讲不出模块怎么跑）** | 文档看起来完整，实际是"没读懂就下结论" | 先能用自己的话讲清运行原理（生产→处理→消费）再进入下一步 |

## 4. 完成判据（Done When）

- [ ] 哲学一手材料已读（列清单：读了哪几篇、关键结论各一句）；
- [ ] 对象涉及的代码接缝已核验（列 文件:行号）；**每个接缝能用一句话讲清运行原理（生产→处理→消费）**；
- [ ] **全部关键判断带证据等级（已验证/推断/未知），无"推断冒充确认"、无"未知处下判断"**；
- [ ] 内核自述含"一句话 + 公理 + 辨析例"；
- [ ] 差距矩阵每行单命题、带性质分类；
- [ ] 分层根因回答了"为什么现有机制被架空"；
- [ ] 参照系含"该学/不该学/独有约束"；
- [ ] 思维链 ≥8 条且 Z 可观察；
- [ ] 三线指标 + 反退化红线齐备；
- [ ] delta 落进设计稿（版本号/变更记录/决策点更新）；
- [ ] `references/checklist.md` 全过或未过项已登记。
