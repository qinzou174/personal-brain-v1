# Deep-Reflection 自检清单（交付前逐项过）

> 用法：反思文档交付前逐条打勾；未过项必须在交付中如实登记（不得静默跳过）。
> 参考实例（本项目首份思维链文档）：`docs/tasks/design-20260924-主体统一与实例隔离/03-思考路径.md`

## A. 接触真实自检（认识论：是否真的贴近了真实）

- [ ] A1 哲学文档：列出本次实际读的篇目（至少 00/01/02/10；领域篇按主题加读），每篇写一句"我读到的关键结论"
- [ ] A2 被反思文档：全文读过；引用其原话时用引号并给小节号
- [ ] A3 代码接缝：对象声称触达的每个代码位置，已实际打开核验（记 文件:行号）；**凡"项目没有 X / 项目有 X"的判断，必须有 grep/读码证据**
- [ ] A4 运行证据：来自既有审查台账（不重做全量统计）；台账缺失时明确标注"未验证"
- [ ] A5 **运行原理**：每个接缝/模块能用一句话讲清"实际怎么跑、为什么这样跑"（生产→处理→消费）；讲不出 = 未完成，回去继续读
- [ ] A6 **证据分层**：全部关键判断标注 `已验证`（实际核对过 文件:行号/日志行号）/ `推断` / `未知`；无"推断冒充确认"、无"未知处下判断"
- [ ] A7 **bug/异常类对象**：已走到真实运行路径（代码链路 + 日志原行抽样）；bug 报告只作线索、未当证据
- [ ] A8 **能讲给外行听懂**：把"它怎么跑"用一段白话讲给不读代码的人，对方能复述大意

## B. 理解自检（是否证明理解）

- [ ] B1 一句话回答"这个项目在造什么"——无泛词（不出现"AI 陪伴系统"式表述）
- [ ] B2 提炼 3–4 条不可让渡公理，每条附"工程上最易踩塌的形态"
- [ ] B3 至少一个**真实运行案例的辨析**（说明某行为的哲学是非，如"001 说渴不是 bug"式辨析）
- [ ] B4 辨析结论**改变了修法方向**（若辨析无实际影响，说明还没挖到位）

## C. 诊断自检（差距与根因）

- [ ] C1 差距矩阵每行只含一个可独立判定的命题；证据带行号；性质三分类（哲学错位/链路断裂/工程故障）
- [ ] C2 "哲学错位"行全部排在前列，并说明"功能都在、错在谁在驾驶"
- [ ] C3 分层根因 3–6 层，每层有：白话 + 证据 + **独立修法**
- [ ] C4 明确回答"为什么现有机制会被架空"（优先修接缝 ★ 禁止无证据断言"必须重建"）
- [ ] C5 若存在"事件→记忆→行为"类链路，必须走全链（生产→存储→消费→最终行为），不得只看写入成功

## D. 参照系自检

- [ ] D1 每个参照三段式：它是什么 → 对得上本项目什么 → 该学/不该学（边界）
- [ ] D2 独有约束清单齐备（多实例隔离 / 双端权威 / 行为验收 B+GBC / 人格引用式与第一人称）
- [ ] D3 若用参照当"尺子"扫本项目（如 CoALA 三轴），缺槽结论需与独立证据互证（≥2 个来源指向同一缺口）

## E. 推导自检（思维链与指标）

- [ ] E1 思维链 ≥8 条，格式「因为 X（哲学/证据）→ 所以 Y → 预期 Z」；X 带出处，Z 可观察
- [ ] E2 设计条目**全部**能从链条引用；链条之外无设计（防"方案先行"）
- [ ] E3 三线指标（最低/中间/高线）每条含：口径 + 现状值 + 目标值，均可机检
- [ ] E4 反退化红线 ≥4 条（覆盖 R7 词表 / R12 表达不消费未完成状态 / R3 不脚本化 / R1 用户话语不直接成行为）

## F. 落地自检（delta 与决策点）

- [ ] F1 delta 清单：每条含「改什么 + 依据 + 预期」；涉及命名/状态词的条目标注**哲学词典对齐检查**（10 号文档逐字对齐）
- [ ] F2 原设计稿已同步：版本号升级 + 变更记录追加 + 相关小节内联 `ΔN` 标注
- [ ] F3 新增决策点续排编号（D 序列）；**哲学张力不得自行消化**（如"主体性 vs 防饿死安全网"必须显式交给创始人拍板）
- [ ] F4 每个决策点给"我的建议 + 理由"（可单选），便于拍板

## G. 交付自检

- [ ] G1 白话+举例：每个发现/设计项都配白话与举例（证据层保留行号，不被白话替代）
- [ ] G2 对话层总结：一句话结论 + 关键发现（≤6）+ 待拍板项清单
- [ ] G3 未通过项/未验证项已如实登记（R11 诚实优先）
- [ ] G4 产出落在 `docs/tasks/design-<YYYYMMDD>-<主题>/`，命名与既有系列一致

## H. 反模式速查（出现即停手重做）

| 编号 | 反模式 | 一句话纠正 |
|---|---|---|
| A1 | 凭印象写"没有 X" | 先读代码证据 |
| A2 | 只横向统计 | 走纵向全链 |
| A3 | 引用编号代替理解 | 自述内核 + 辨析例 |
| A4 | 一切问题="缺功能" | 差距三分类 |
| A5 | 单一根因 | 分层根因 |
| A6 | 硬套开源 | 参照带边界 |
| A7 | 先方案后理由 | 方案从链条引用 |
| A8 | 自造状态词 | 对齐哲学词典 |
| A9 | 无表现指标 | 三线 + 反退化 |
| A10 | 替创始人消化张力 | 显式决策点 |
| A11 | 证据未分层（推断冒充已确认） | 标注 `已验证/推断/未知`；未知处不下判断 |
| A12 | 跳过系统理解直接产出（讲不出模块怎么跑） | 先能讲清运行原理再进入下一步 |
